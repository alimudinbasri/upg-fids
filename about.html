1. Ringkasan Aplikasi

M-FIDS adalah sistem informasi penerbangan mobile untuk Bandara Sultan Hasanuddin International Airport (Makassar, kode IATA UPG). Aplikasi ini dipakai oleh staf operasional bandara (sehari-hari, bukan demo/prototipe) untuk memantau jadwal kedatangan/keberangkatan real-time, mengatur penempatan gate & belt, melihat laporan on-time performance (OTP), dan menganalisis data historis penerbangan.

  • Live production URL: https://upg-fids.web.app
  • Firebase project ID: upg-fids
  • Repo GitHub: github.com/alimudinbasri/upg-aolt, branch main
  • Working directory server: C:\xampp\htdocs\fids (Windows Server VM)

2. Tech Stack & Arsitektur

Ini adalah static site multi-halaman berbasis vanilla JavaScript — bukan React/Vue/Angular, tidak ada build step (webpack/vite), tidak ada bundler, tidak ada npm package untuk runtime app. Setiap halaman .html adalah file mandiri lengkap dengan <style> dan <script> inline miliknya sendiri.

Penting untuk dipahami: tidak ada sistem template/include bersama. Boilerplate seperti header, hamburger nav, jam digital, dan tab bar mobile diduplikasi manual di setiap file HTML. Kalau mengubah salah satunya (misalnya menambah link navigasi), perubahan itu harus diterapkan berulang ke semua halaman yang relevan — ini pola yang disengaja mengingat ukuran proyek, bukan kelalaian.

Komponen utama

  • Frontend: HTML + CSS + vanilla JS (ES5-ish, pakai var/function lebih banyak daripada let/arrow function, demi kompatibilitas luas)
  • Hosting: Firebase Hosting
  • Auth: Firebase Authentication (Google Sign-In)
  • Database: Cloud Firestore (native mode)
  • Sumber data penerbangan: Google Apps Script (GAS) web app eksternal, membaca dari sistem AIS bandara
  • Charting: Chart.js + chartjs-plugin-datalabels (dipakai di analytics.html), dimuat dari CDN (jsdelivr), tanpa versi di-pin secara eksplisit
  • PDF export: jsPDF + jspdf-autotable (dipakai di index.html)

Modul bersama hasil refactor (September 2026)

Empat modul di bawah ini lahir dari penghapusan duplikasi copy-paste antar halaman. Semuanya dimuat di slot yang sama dengan app-config.js, yaitu sebelum seluruh inline script halaman.

Tidak memuat tickClock(): analytics/index menampilkan tanggal dalam Bahasa Inggris, real_gate/real_belt/laporan dalam Bahasa Indonesia — membaginya berarti mengoper array nama hari/bulan, yang justru isi fungsinya.
  • js/wa-report.js — WaReport.create(cfg) + WaReport.showToast()/renderTemplate(). getDefaultWaTemplate() dan buildWaTagData() tetap di tiap halaman karena empat laporan itu memang berbeda, bukan empat salinan. Jebakan: halaman memasang listener dengan referensi fungsi telanjang dari init yang jalan lebih awal di file, jadi wrapper-nya harus function declaration (ter-hoist) dengan singleton malas — var x = api.close akan mematikan tombol tanpa error apa pun.

js/auth-guard.js

Tugasnya: cek maintenance mode (baca publik), redirect ke login jika belum auth, cek status blokir, catat activity_logs + presence + user_logs, expose window.CURRENT_USER/window.IS_ADMIN/window._db ke halaman pemanggil, dan reveal elemen nav #nav-admin-link/#nav-about-link kalau user adalah admin.

5. Sumber Data Real-time (AIS / Google Apps Script)

Data penerbangan (bukan histori) berasal dari sebuah Google Apps Script web app di luar repo ini, yang membaca sistem AIS bandara. Nama proyek Apps Script: "FIDS - AirportsOne" (lihat §10).

GET {gasUrl}?action=arrival&date=YYYY-MM-DD GET {gasUrl}?action=departure&date=YYYY-MM-DD // respons (JSON): { "ok": true, "action": "arrival", "date": "2026-09-11", "data": [ {...row}, ... ] }

Field penting per baris (nama field asli dari AIS, dipakai apa adanya oleh frontend): nopen (nomor flight, mis. "JT-798"), icao_code, iata_code (kode kota tujuan/asal), city, time/schedule, estimate, actual, remark (status teks, mis. "Landed"/"Departed"/"Delay operational"), gate (untuk departure), belt (untuk arrival), bay_id (parkir pesawat), pax, reg (registrasi pesawat), type (tipe pesawat).

✓ Bug JSONP — ditemukan & diperbaiki (September 2026): endpoint GAS ini hang/error kalau parameter callback=... disertakan (dites langsung: permintaan tanpa callback selesai <1 detik dengan JSON valid dan header Access-Control-Allow-Origin: *; dengan callback, permintaan timeout total). Awalnya ditemukan lewat testing lokal, lalu dikonfirmasi terjadi juga di production saat index.html (papan FIDS utama) macet total di "No flight data" / "Menunggu sinkronisasi data pertama…" — ini kemungkinan penyebab utama laporan "lambat" yang berulang dari admin selama ini. Kelima halaman yang memanggil GAS langsung (index.html, otp.html, real_gate.html, real_belt.html, analytics.html) sudah diganti dari pola JSONP (<script> tag + parameter callback) menjadi fetch() biasa tanpa callback, memanfaatkan CORS yang sudah permisif di endpoint ini.

6. Cache Historis (Firestore flights_cache)

analytics.html dan laporan.html butuh data berhari-hari sekaligus, dan memanggil GAS secara live untuk itu terlalu lambat. Solusinya: koleksi Firestore flights_cache/{date} (satu dokumen per tanggal YYYY-MM-DD) diisi oleh proses Apps Script terjadwal (§10).

Skema dokumen (dikonfirmasi via Firebase Console, September 2026)

flights_cache/2026-09-11 { arrivals: // STRING berisi JSON array, BUKAN array Firestore asli! "[{\"nopen\":\"ID-6136\",\"icao_code\":\"WARR\",\"iata_code\":\"SUB\",...}, ...]", departures: "[{...}, ...]", // sama, string JSON updatedAt: "2026-09-11T15:59:21.212Z" }
Hati-hati: nilai arrivals/departures adalah string hasil JSON.stringify(), harus di-JSON.parse() dulu sebelum dipakai — bukan array Firestore native. Ini sempat jadi bug ("0 cached, semua live") karena parser awal hanya mengecek Array.isArray().

Fungsi parseFlightsCacheDoc() menangani shape ini (field arrivals/departures, plural). Sejak commit 57a58c3 fungsi ini hanya menerima schema tersebut — tiga fallback tebakan lama (arrival/ARR/flights) sudah dihapus setelah schema asli dikonfirmasi. Kalau hari tertentu belum ada di cache (atau gagal parse), otomatis fallback ke live fetch ke GAS.

Duplikasi: laporan.html punya salinan sendiri dari lapisan akses data ini (parseFlightsCacheDoc, toRowArray, fetchDayLive, fetchDayFromCache, waitForDb, extractRows, dateRangeList, …) — sebagian byte-identik dengan versi di analytics.html. Perbaikan bug di satu file harus diterapkan juga di file satunya. buildFlight() sengaja berbeda: versi laporan.html hanya mengambil 5 field (date/type/flightNo/gate/belt) karena laporan tidak butuh sisanya.

Status backfill

Batas tanggal paling awal yang bisa dipilih di analytics.html (datasetStart) di-hardcode ke 2026-01-01, mengasumsikan backfill sudah/akan mencakup rentang itu. Backfill dijalankan via flights_cache_backfill.gs (§10) — cek status terakhir di admin/Apps Script langsung, dokumen ini tidak melacak progres backfill secara live.

8. Aturan Keamanan (Firestore Rules)

Ringkasan firestore.rules (per koleksi, lihat file aslinya untuk detail lengkap):

  • isHardcodedAdmin() — true kalau email login ada di 3 alamat admin tetap (harus sinkron manual dengan APP_CONFIG.adminEmails)
  • isAdmin() — hardcoded admin ATAU punya dokumen di /admins (sumber kebenaran; bukan /admin_uids, karena itu bisa ditulis sendiri oleh user manapun dan tidak boleh dipakai untuk cek admin — celah eskalasi privilege yang sudah diantisipasi)
  • activity_logs — siapapun boleh create (harus self-attributed uid/email), hanya admin boleh baca semua/hapus
  • presence — user hanya boleh tulis/hapus data dirinya sendiri, admin boleh hapus siapapun
  • blocked_users — user login boleh cek statusnya sendiri, hanya admin boleh list semua/tulis
  • admins — semua user login boleh baca, hanya hardcoded admin boleh tulis
  • wa_settings — semua user login boleh baca, hanya admin boleh tulis
  • flights_cache — semua user login boleh baca, hanya akun gas-sync@upg-fids.internal boleh tulis
  • site_config — baca publik (perlu dicek sebelum user login, untuk redirect maintenance), tulis hanya admin

9. Model Otentikasi & Admin

Login pakai Firebase Auth dengan Google Sign-In (tidak ada email/password untuk user biasa). Ada dua jenis admin:

  • Admin hardcoded (utama) — 3 alamat email tetap di APP_CONFIG.adminEmails (dan cermin di firestore.rules). Hanya mereka yang boleh menambah/menghapus admin dinamis.
  • Admin dinamis — email dengan dokumen di koleksi admins, ditambahkan admin utama lewat admin.html.

Catatan arsitektur penting: admin.html (dan about.html ini) tidak memakai js/auth-guard.js yang dipakai halaman lain — keduanya punya auth-gate inline sendiri yang eksplisit memblokir non-admin (redirect ke login.html?error=unauthorized), bukan sekadar menyembunyikan link nav seperti pola di halaman lain. Kalau membuat halaman admin-only baru, tiru pola ini (lihat kode about.html), jangan pakai js/auth-guard.js yang hanya mengizinkan-tapi-menyembunyikan.

Ada satu akun Firebase Auth khusus non-manusia: gas-sync@upg-fids.internal (email+password, kredensial tersimpan di Script Properties Apps Script) — satu-satunya identitas yang diizinkan menulis ke flights_cache.

10. Otomatisasi Backend (Google Apps Script)

Proyek Apps Script bernama "FIDS - AirportsOne" di script.google.com — di luar repo Git ini, dikelola terpisah lewat editor Apps Script. Berisi:

Code.gs

Script utama, meng-handle doGet() yang melayani ?action=arrival|departure&date= (lihat §5) — sumber data mentah dari sistem AIS bandara.

gas_sync_snippet.gs — aktif

Fungsi syncFlightsToFirestore(), dijalankan trigger waktu setiap 2 menit. Alurnya: fetch arrival+departure hari ini dari Code.gs sendiri → sign-in sebagai gas-sync@upg-fids.internal lewat Firebase Auth REST API (identitytoolkit.googleapis.com/v1/accounts:signInWithPassword) → tulis ke Firestore lewat REST API (firestore.googleapis.com/v1/.../flights_cache/{date}, method PATCH) pakai token hasil sign-in. Kredensial di Script Properties: SYNC_EMAIL, SYNC_PASSWORD.

flights_cache_backfill.gs — backfill berjalan

Ditambahkan untuk mengisi histori sebelum sync 2-menit itu mulai berjalan. Dua fungsi:

  • backfillFlightsCache() — one-time, resumable (progres tersimpan di Script Property BACKFILL_CURSOR), mengisi dari 2026-01-01 sampai kemarin, maks ~40 hari atau 5 menit per eksekusi (menghindari limit eksekusi Apps Script), menghapus trigger dirinya sendiri saat selesai (log "Backfill complete.")
  • dailyResyncFlightsCache() — dijalankan trigger harian, menulis ulang 5 hari terakhir setiap kali jalan, untuk menangkap koreksi data AIS yang datang belakangan (jam aktual direvisi, pax difinalkan, dst.) — desain ini menangani kasus "data historis bisa berubah" tanpa perlu backfill ulang seluruh histori.

Kedua fungsi baru ini menggunakan mekanisme sign-in & format tulis persis sama dengan gas_sync_snippet.gs (disalin dari kode yang sudah terbukti jalan), lewat fungsi bersama syncOneDate_().

12. Desain & Konvensi UI

  • Tema warna: dark-first, :root = dark, :root[data-theme="light"] = override terang. Toggle tersimpan di localStorage per halaman.
  • Palet: teal (#00bcd4) sebagai warna aksen utama, navy gelap (#0a1628/#0d1e35) sebagai latar.
  • Header + hamburger nav: pola identik di semua halaman (lihat §2) — drawer nav kiri, overlay gelap, tombol logout di bawah.
  • Tab bar mobile bawah: muncul di lebar layar ≤720px, berisi FIDS/Gate/Belt/OTP/Analytics/Laporan (Admin & About sengaja tidak dimasukkan, cukup lewat drawer nav).
  • Chart.js pada analytics.html & laporan.html: instance chart disimpan supaya bisa di-redraw ulang saat ganti tema (canvas tidak auto-update warna saat CSS variable berubah — ini sempat jadi bug di real_gate/real_belt sebelum dihindari di analytics.html sejak awal).
  • Versi library CDN di-pin persis (commit cb8b6ac): chart.js@4.5.1, chartjs-plugin-datalabels@2.2.0, jspdf@2.5.1, jspdf-autotable@3.5.25, html2canvas@1.4.1, xlsx@0.18.5, Firebase compat 9.23.0. Jangan pernah pakai URL tanpa nomor versi (npm/chart.js) atau range mayor (@2): rilis breaking dari upstream bisa mematikan produksi tanpa ada perubahan kode di sisi kita, dan tidak bisa direproduksi lokal. Naik versi harus jadi commit tersendiri yang bisa diuji dan di-revert.
  • Bahasa UI: analytics.html sudah full Bahasa Inggris (atas permintaan eksplisit); halaman lain (index/real_gate/real_belt/otp/admin) masih Bahasa Indonesia.

Keduanya dikonfirmasi tidak disengaja dan diseragamkan; opsi iconLight/iconDark/stampDark dihapus dari ui-chrome.js agar tidak jadi celah divergensi lagi.
  • Cleanup buildWaTagData() di index.html masih hardcode pengelompokan terminal TS/TE/INTER berikut label tampilannya. Sengaja tidak diubah saat 9a45687: ini pengelompokan terminal, bukan status DOM/INT, dan tidak bisa diturunkan dari gateMeta. Menurunkan array-nya sambil membiarkan label tetap hardcode justru menambah risiko drift. Perbaikan yang benar butuh konsep gateGroups baru di app-config.js.
  • Cleanup Drift palet CSS. real_gate.html berbeda dari index.html pada 21 dari 31 variabel :root, real_belt 19, analytics 15. Maksud visualnya sama, nilainya menyimpang. Kosmetik, tapi memburuk tiap kali ada edit.
  • Cleanup esc() ada di index/otp/real_gate/real_belt tapi tidak ada di analytics.html, yang merender field AIS lewat konkatenasi mentah (route, city, airline, flightNo). Severity rendah selama sumber AIS tepercaya dan flights_cache terkunci ke akun sync — naik prioritas hanya jika sumber data diperluas.
  • Cleanup activity_logs tumbuh tanpa batas (satu dokumen per pageview). Hanya ada purge manual per-batch di admin.html; belum ada TTL policy atau cleanup terjadwal.
  • Catatan emailToKey() ada 3 salinan (auth-guard.js, admin.html, firestore.rules) dan adminEmails 2 salinan (app-config.js, firestore.rules). Stabil dan terdokumentasi, tapi divergensi akan gagal open di klien dan closed di rules — kombinasi yang sulit didiagnosis.
  • Catatan Tidak ada test, CI, atau linting. Verifikasi sepenuhnya manual lewat browser. Untuk basis kode 616 KB dengan ~55% inline JS, seluruh risiko regresi ditanggung oleh review manusia.
  • Catatan sw.js sengaja dimatikan (cache-killer) — tepat untuk data real-time, tapi manifest.json masih mengiklankan display: standalone + shortcuts, jadi peluncuran offline akan menampilkan error, bukan konten cache.

14. Catatan Riwayat

Insiden reversion Git/file (dugaan snapshot VM): pernah terjadi HEAD branch main mundur beberapa commit tanpa entri reflog, dan beberapa file working-tree kembali ke versi lama — berulang, bahkan untuk file yang baru saja diedit di sesi yang sama. Dugaan kuat: restore snapshot VMware pada mesin Windows Server ini. Mitigasi yang dianut sejak saat itu: commit & push setelah setiap perubahan kecil dan diskrit, bukan menumpuk banyak perubahan sebelum commit — supaya kalau insiden serupa terulang, kerugiannya minimal.

Bug halaman blank: index.html pernah kehilangan tag <script src="js/app-config.js"> (korban insiden di atas), menyebabkan ReferenceError di auth-guard.js dan halaman tetap visibility:hidden selamanya. Diperparah oleh firebase.json yang hanya meng-cache *.@(js|css|html), bukan root path — browser sempat cache respons rusak sampai 1 jam. Sudah diperbaiki di kedua sisi.

Dokumen ini ditulis manual berdasarkan investigasi kode & diskusi pengembangan — perbarui bagian yang relevan setiap kali ada perubahan arsitektur signifikan, supaya tetap akurat untuk pembaca berikutnya (manusia atau AI).
